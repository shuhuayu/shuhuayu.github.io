Most layers carry a recurrent state

Thirty-six GDN layers summarize history in fixed-size matrices; twelve QSA layers retain token-growing K/V caches.

Sparsity selects what to read

A lightweight indexer scores four-token blocks. The main attention reads up to 512 complete blocks, plus the current partial block.

Residual capacity grows to four streams

Lexical capacity uses sparse lookups

Sixteen bigram/trigram hash heads retrieve 160 features each. A 51.2B table supplies 2560 lexical features per token.

04 / Work through the residual path

Read four streams, compute once, write four updates

Each attention or MoE sublayer begins with H [T, 4, 2560]. It produces a single input [T, 2560], computes its update, then adds a scaled copy of that update to every stream. The read and write gates are predicted from the current hidden state.

The example uses D = 2 and rank 2 so every value fits on screen. The production shapes shown beside it use D = 2560 and rank 320. The fixed sublayer update [0.8, -0.4] stands in for attention or MoE; it is not computed by those kernels here. The slider adds a teaching offset, not a bias parameter in the release.

Read: one gate per stream and channel

The read gates are [T, 4, 2560]. Multiply them by the independently normalized streams, then average across the four streams. Sigmoid gates do not have a fixed sum across streams.

Write: one scalar per stream

The write projection maps [T, 10240] to [T, 4]. Gates are 2 × sigmoid(logits / 4): a zero logit gives 1, and the range is 0 to 2. Broadcast each scalar over all 2560 channels of the sublayer output.

Attention and MoE have separate mixers. After layer 48, a final read-only mixer produces [T, 2560] for the LM head. Its grouped normalization is part of the mixer; the reference has no separate final RMSNorm. Reference implementation.

06 / The recurrent layers

GDN updates a small matrix of history

A key addresses the state, a value supplies new content, and a query reads the updated state. The delta rule first predicts the value already stored under the key, then writes a gated correction. Each of the 36 GDN layers has its own state.

One illustrative head / key width 2, value width 2

Forget, predict, correct, read

Release: 48 states of [128, 128] per layer
S_decayed = α × S_previous
prediction = kT S_decayed
S_new = S_decayed + β k (v - prediction)T
output = qT S_new

S has key channels as rows and value channels as columns. Q/K are normalized in the actual model. Decay comes from learned projections and a softplus/exponential transform; β comes from sigmoid. The controls directly choose the resulting gate values.

Decode carries bounded state

Each layer carries [48, 128, 128] state plus short convolution history for each active sequence. Across 36 layers, the matrices occupy 108 MiB at FP32, regardless of prefix length.

Training still processes every token

Chunked kernels parallelize the recurrence. Backward needs Q/K/V, gates, and kernel-specific summaries, retained or recomputed. A fixed-size decode state does not make total training activation memory constant.

The release projects 16 Q/K heads and 48 value heads; each Q/K head serves three value heads. Per-head output RMSNorm and sigmoid gating precede the 6144 → 2560 output projection. Configuration · Reference.

The released model uses the same block size of four, with a 2048-token budget. The scores here illustrate selection mechanics and are not predictions from the checkpoint.

Sparse reads keep a growing cache

A later query may choose an old block, so main K/V remain available. The pinned reference also keeps raw indexer keys. A bounded read budget is not a bounded stored prefix.

Search and attention have different scaling

One decode query scores roughly N/4 block keys, then attends to at most 2048 + 3 tokens. Across a whole prefill, indexer search still has quadratic work. Fused sparse kernels and chunking matter at long contexts.

How does the indexer learn its selection?

The report first distills a dense-attention teacher into the indexer, then jointly trains with sparse attention. The sparse-stage teacher sums detached main-attention probabilities across heads, max-pools within each selected complete block, and normalizes over selected blocks. The KL loss trains selected indexer scores; integer top-k IDs are not differentiable. Teacher detachment and any detachment of the indexer's hidden input are separate decisions. The report does not specify a KL coefficient, so this page does not assign one.

08 / Learn features for short token patterns

PLE starts with token IDs, then retrieves learned rows

An ordinary embedding gives good one vector. A pair embedding could give very good and not good different additional vectors. PLE implements this idea with bigram and trigram hashes, a large learned table, and contextual gates.

The simplest version of the idea 
extra = pair_embedding[previous_id, current_id]
hidden = hidden + extra

Training learns the extra feature vector. Attention can also learn these relationships; PLE adds another place to store short-pattern features.

Why add hashing and multiple heads?

A direct table for all 248,3202 pairs would need about 61.7 billion rows; triples need far more. Hashes assign patterns to a chosen bucket budget. Several heads give each pattern multiple lookups, so one collision need not make two patterns indistinguishable.

The words have illustrative IDs, independent of the real tokenizer. Hashing uses signed 64-bit products/XOR, distinct prime bucket counts, and head offsets from the pinned reference configuration. Displayed row vectors are synthetic, not checkpoint values.

Token content determines the addresses

Offsets t, t-1, and t-2 choose the recent IDs. The same pattern at another absolute position selects the same rows. Document boundaries and EOS reset the available history; missing tokens use the EOS ID.

Capacity and traffic are different

The table is [320,001,536, 160]: 51.2B parameters, or 95.37 GiB at BF16. A token reads only 16 × 160 elements, or 5 KiB, before the projections. More buckets reduce sharing; they also increase weight and optimizer storage.

IDs can be prepared before activations arrive

Hash addresses depend on original IDs. The report places PLE at layer 2 so its system can prefetch rows while layer 1 runs. A host prefetch implementation needs a row owner, transfer buffers, and a backward update policy.

A lookup is still learned model capacity

Rows are parameters trained through the downstream loss. Multiple uses of a row contribute gradients to that row. Selecting a few rows does not by itself guarantee sparse gradient tensors or sparse optimizer work.

PLE enters before layer 2's attention read. Its gated values are refined by a per-channel causal convolution with taps at t, t-3, t-6, and t-9; the result is added to the existing streams. Hashing resets at EOS and document starts; the convolution resets at document starts. Reference implementation.

MoE turns tokens into token-expert assignments

The MoE read gives x [T, 2560]. Each token chooses ten routed experts from 512; one shared expert also processes every token. Expert parallelism assigns expert weights to owners and sends each assignment to the right owner.

10 / Infrastructure and gradients

Name the owner and lifetime of every tensor

Model capacity, serving state, saved activations, and optimizer state obey different scaling rules. A sharding plan must say which rank owns each value, when it communicates, and how backward returns its gradients.

Logical sizes / one decoder boundary and one expert dispatch

Four streams change activation traffic

Sizes, not measured peak memory

SP here shards the carried token dimension. It does not imply every intermediate remains sharded. The expert payload counts all ten assignments per token over the expert group; local assignments and wire traffic depend on routing and placement. Original IDs and document positions are counted separately at full logical T.

Compilation and scheduling must preserve the computation

Keep selections and BF16 rounding faithful

Fusion must preserve the router's activation-dtype rounding before softmax/top-k. Dynamic block construction and selection need explicit CUDA graph support or a clear unsupported configuration.

Batch work across query chunks

Bounded temporary tensors help memory, but Python loops, repeated metadata synchronization, and one collective per small chunk can dominate. Aggregate teacher reductions where possible and measure the selected kernel path.

Optimizer assignments follow parameter roles

Muon for genuine linear maps

Attention/GDN projections, expert matrices, and PLE key/value projections use Muon. Fused matrices are split into their semantic operators before orthogonalization; the report uses per-head splitting for attention and GDN.

AdamW where the structure differs

Input/output tables, routers, and GR's elongated low-rank projections use AdamW. The n-gram table uses Adam with weight decay disabled. The optimizer assignment follows the role and shape of each weight.

Prefetch lexical rows early

Hash addresses depend on token IDs, so lookups can be prepared before the decoder reaches PLE. Placing PLE at layer 2 creates overlap with layer 1's computation and makes host-memory storage practical in the report's system.

Distill before sparse training

A dense-attention teacher first trains the indexer. Sparse continued pretraining then adapts both the backbone and indexer. The report's QSA objective learns block relevance from detached main-attention probabilities.

Reported kernel efficiency: at a 1M context, the report measures 7.6× prefill and 4.9× decode speedups for the attention module, including indexing and sparse attention. Its settings use 16K chunked prefill at batch size 1, and decode at batch size 4 with speculative steps. These measurements apply to the report's fused kernels and benchmark settings.

The report also refits batch-size and learning-rate scaling laws and starts at the target batch size without traditional batch-size warmup. GR's gated normalization is evaluated for training stability under larger learning rates.

Reference: six component specifications

The three main additions are QSA, gated residuals, and lexical embeddings. GDN, routed experts, and the vision pathway remain the foundation of the hybrid decoder. [1]

Gated DeltaNet: history in a fixed-size state

GDN is a gated delta-rule recurrence. Short causal convolutions prepare Q/K/V; a decay gate forgets old state, and a beta gate controls a corrective write. Chunked training computes this recurrence in parallel; token-by-token decoding carries the state forward.

Sixteen Q/K heads feed forty-eight value heads, so each Q/K head serves three value heads. The output uses per-head RMS normalization and a sigmoid gate in this release. [4]

Two training stages

The report introduces QSA during continued pretraining: first distill a dense-attention teacher into the indexer, then jointly train the backbone and indexer with sparse attention and a selected-block KL objective.

Two different costs

The sparse attention core reads a bounded token budget. The indexer still scores the growing set of compressed blocks; whole-sequence prefill indexing remains quadratic in sequence length, reduced by the factor-four compression.

Gated residual: four streams, one sublayer input

The persistent residual is [T, 4, 2560], or [T, 10240] when flattened. Each stream is normalized independently. A 10,240 → 320 → 10,240 bottleneck predicts an element-wise sigmoid read gate. Averaging the gated streams produces a width-2560 input for the sublayer.

Four scalar write gates send the sublayer's output back into the four streams. Attention and MoE have independent read/write modules. A final read-only mixer reduces the streams before the LM head; the reference has no separate final RMSNorm. [4]

Width in the residual path

Attention and expert projections operate at D = 2560. The wider residual path increases activation traffic and gives the model different learned reads of accumulated information.

Compared with Kimi's Attention Residuals

Kimi K3 retrieves earlier depth summaries using attention. GR keeps four streams and learns channel-wise read gates plus scalar writes. Its design omits an additional stream-to-stream residual mixing matrix.

Lexical embeddings: a large table with a small read

Eight bigram and eight trigram hash heads each address a distinct prime-sized vocabulary near twenty million slots. Their tables are concatenated into 320,001,536 padded rows, each with 160 features. Sixteen lookups concatenate to [T, 2560].

The lexical features project to one shared value and four stream-specific keys. Normalized residual streams gate the value. A width-four causal convolution with dilation three adds local lexical context. The result is added before layer 2's attention read. [2]

Weight capacity and bandwidth

The BF16 table alone is 95.37 GiB. Each token reads 5 KiB of lexical features before projections. The report places PLE at layer 2 so predictable lookups can be prefetched from host memory while layer 1 runs.

Token metadata must survive

Hashing requires original IDs and resets history at EOS. Packed training also needs document boundaries, including when PLE lives on a later pipeline stage. Multimodal rotary coordinates do not replace that lexical history.

MoE: 512 experts behind a width-640 intermediate

Every layer routes each token to ten of 512 SwiGLU experts and also evaluates one shared expert. Each expert has gate, up, and down matrices at widths 2560 and 640. Selected router probabilities are normalized; the shared expert has its own sigmoid output gate.

Routing uses FP32 softmax on activation-rounded logits, then casts expert mixing weights to the activation dtype. Small BF16 rounding differences near a tie can change the discrete expert IDs. [4]

Storage versus selected matrices

The routed bank holds 120.796B weights. Ten experts per token select 2.359B of those weights across all layers. Routers, attention, residual mixers, and the LM head add to the token's active path.

Expert parallelism

Dispatch and combine exchange token activations across expert owners. R is a logical group-wide assignment count; expert imbalance and placement determine how many assignments each GPU receives.

Vision: patch tokens enter the same decoder

A twenty-seven-layer vision transformer uses width 1152, sixteen heads, and intermediate width 4304. A spatiotemporal patch embedding consumes [3, 2, 16, 16] patches for images and video. A 2 × 2 spatial merge projects visual features to width 2560.

The decoder uses interleaved multimodal rotary coordinates: 64 rotary channels in a 256-channel main attention head, with temporal/height/width sections [11, 11, 10]. The released configuration has no deepstack visual injection layers. [2]

Variable visual token counts

Image resolution, video sampling, and patch merging determine the decoder's visual token count. Visual tokens consume context and follow the same decoder attention and MoE paths.

Native and extended context

The checkpoint sets 262,144 positions and RoPE theta 10,000,000. The model card describes YaRN extension to 1,000,000 tokens. The hosted Qwen3.8-Flash product advertises a default 1M context and additional built-in tools.
