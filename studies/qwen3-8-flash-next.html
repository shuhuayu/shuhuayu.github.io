The model at a glance

Forty-eight decoder layers repeat a four-layer rhythm twelve times: GDN, GDN, GDN, QSA. Every layer has 512 routed experts and one shared expert. Lexical embeddings enter at layer 2; separate gated residual modules surround attention and MoE in every layer. [2]

Most layers carry a recurrent state

Thirty-six GDN layers summarize history in fixed-size matrices; twelve QSA layers retain token-growing K/V caches.

Sparsity selects what to read

A lightweight indexer scores four-token blocks. The main attention reads up to 512 complete blocks, plus the current partial block.

Residual capacity grows to four streams

Each sublayer reads a learned channel-wise mixture of the streams, computes at width 2560, and writes through one scalar gate per stream.

Lexical capacity uses sparse lookups

Sixteen bigram/trigram hash heads retrieve 160 features each. A 51.2B table supplies 2560 lexical features per token.

One decoder, six views

The three main additions are QSA, gated residuals, and lexical embeddings. GDN, routed experts, and the vision pathway remain the foundation of the hybrid decoder. [1]

Gated DeltaNet: history in a fixed-size state

GDN is a gated delta-rule recurrence. Short causal convolutions prepare Q/K/V; a decay gate forgets old state, and a beta gate controls a corrective write. Chunked training computes this recurrence in parallel; token-by-token decoding carries the state forward.

Sixteen Q/K heads feed forty-eight value heads, so each Q/K head serves three value heads. The output uses per-head RMS normalization and a sigmoid gate in this release. [4]

Persistent state

The thirty-six recurrent matrices occupy 108 MiB at FP32 per sequence, independent of context length. Short-convolution history adds a small fixed term.

Compute and normalization

The main projections produce QKV width 10,240 and gate width 6,144. The beta and decay projections each produce 48 scalars per token. State accumulation and normalization use higher precision than BF16 activations.

Qwen Sparse Attention: select blocks, then read tokens

A small multi-query indexer predicts relevance for complete four-token blocks. It averages raw keys inside each block, then normalizes and applies positional encoding using the first token's position. Four query heads score each block; their rectified scores are summed.

Top-k chooses up to 512 blocks. Main GQA uses the original, unpooled K/V of the selected 2048 tokens, plus up to three tokens in the current incomplete block. Causality and document boundaries apply to both selection and attention. [3]

Two training stages

The report introduces QSA during continued pretraining: first distill a dense-attention teacher into the indexer, then jointly train the backbone and indexer with sparse attention and a selected-block KL objective.

Two different costs

The sparse attention core reads a bounded token budget. The indexer still scores the growing set of compressed blocks; whole-sequence prefill indexing remains quadratic in sequence length, reduced by the factor-four compression.

Gated residual: four streams, one sublayer input

The persistent residual is [T, 4, 2560], or [T, 10240] when flattened. Each stream is normalized independently. A 10,240 → 320 → 10,240 bottleneck predicts an element-wise sigmoid read gate. Averaging the gated streams produces a width-2560 input for the sublayer.

Four scalar write gates send the sublayer's output back into the four streams. Attention and MoE have independent read/write modules. A final read-only mixer reduces the streams before the LM head; the reference has no separate final RMSNorm. [4]

Width in the residual path

Attention and expert projections operate at D = 2560. The wider residual path increases activation traffic and gives the model different learned reads of accumulated information.

Compared with Kimi's Attention Residuals

Kimi K3 retrieves earlier depth summaries using attention. GR keeps four streams and learns channel-wise read gates plus scalar writes. Its design omits an additional stream-to-stream residual mixing matrix.

Lexical embeddings: a large table with a small read

Eight bigram and eight trigram hash heads each address a distinct prime-sized vocabulary near twenty million slots. Their tables are concatenated into 320,001,536 padded rows, each with 160 features. Sixteen lookups concatenate to [T, 2560].

The lexical features project to one shared value and four stream-specific keys. Normalized residual streams gate the value. A width-four causal convolution with dilation three adds local lexical context. The result is added before layer 2's attention read. [2]

Weight capacity and bandwidth

The BF16 table alone is 95.37 GiB. Each token reads 5 KiB of lexical features before projections. The report places PLE at layer 2 so predictable lookups can be prefetched from host memory while layer 1 runs.

Token metadata must survive

Hashing requires original IDs and resets history at EOS. Packed training also needs document boundaries, including when PLE lives on a later pipeline stage. Multimodal rotary coordinates do not replace that lexical history.

MoE: 512 experts behind a width-640 intermediate

Every layer routes each token to ten of 512 SwiGLU experts and also evaluates one shared expert. Each expert has gate, up, and down matrices at widths 2560 and 640. Selected router probabilities are normalized; the shared expert has its own sigmoid output gate.

Routing uses FP32 softmax on activation-rounded logits, then casts expert mixing weights to the activation dtype. Small BF16 rounding differences near a tie can change the discrete expert IDs. [4]

Storage versus selected matrices

The routed bank holds 120.796B weights. Ten experts per token select 2.359B of those weights across all layers. Routers, attention, residual mixers, and the LM head add to the token's active path.

Expert parallelism

Dispatch and combine exchange token activations across expert owners. R is a logical group-wide assignment count; expert imbalance and placement determine how many assignments each GPU receives.

Vision: patch tokens enter the same decoder

A twenty-seven-layer vision transformer uses width 1152, sixteen heads, and intermediate width 4304. A spatiotemporal patch embedding consumes [3, 2, 16, 16] patches for images and video. A 2 × 2 spatial merge projects visual features to width 2560.

The decoder uses interleaved multimodal rotary coordinates: 64 rotary channels in a 256-channel main attention head, with temporal/height/width sections [11, 11, 10]. The released configuration has no deepstack visual injection layers. [2]

Variable visual token counts

Image resolution, video sampling, and patch merging determine the decoder's visual token count. Visual tokens consume context and follow the same decoder attention and MoE paths.

Native and extended context

The checkpoint sets 262,144 positions and RoPE theta 10,000,000. The model card describes YaRN extension to 1,000,000 tokens. The hosted Qwen3.8-Flash product advertises a default 1M context and additional built-in tools.

Sparse reads still use a growing history cache

The 2048-token budget limits which K/V entries a query reads. A future query can select any earlier complete block, so the main K/V history remains token-growing. GDN's recurrent matrices stay constant. The pinned Transformers reference also caches raw indexer keys. [4]

The training recipe follows the architecture

The report treats optimizer choice, residual stability, and memory movement as part of the design. These are findings from the released model's training study. [3]

Muon for genuine linear maps

Attention/GDN projections, expert matrices, and PLE key/value projections use Muon. Fused matrices are split into their semantic operators before orthogonalization; the report uses per-head splitting for attention and GDN.

AdamW where the structure differs

Input/output tables, routers, and GR's elongated low-rank projections use AdamW. The n-gram table uses Adam with weight decay disabled. The optimizer assignment follows the role and shape of each weight.

Prefetch lexical rows early

Hash addresses depend on token IDs, so lookups can be prepared before the decoder reaches PLE. Placing PLE at layer 2 creates overlap with layer 1's computation and makes host-memory storage practical in the report's system.

Distill before sparse training

A dense-attention teacher first trains the indexer. Sparse continued pretraining then adapts both the backbone and indexer. The report's QSA objective learns block relevance from detached main-attention probabilities.

Reported kernel efficiency: at a 1M context, the report measures 7.6× prefill and 4.9× decode speedups for the attention module, including indexing and sparse attention. Its settings use 16K chunked prefill at batch size 1, and decode at batch size 4 with speculative steps. These measurements apply to the report's fused kernels and benchmark settings.

The report also refits batch-size and learning-rate scaling laws and starts at the target batch size without traditional batch-size warmup. GR's gated normalization is evaluated for training stability under larger learning rates.
