40 local caches, 4 global cache pairs

Layer 30 still receives layer 29

KV sharing and selection sharing are separate

Prefill savings concern old prompt positions

Optimized serving skips most decoder work for the prompt. Each generated token and each teacher-forced training token runs all 40 layers.

03 / Follow the hidden state

One block, with its memory sources attached

Start with Layer 30, a decoder Reuse layer. Its incoming hidden state comes from Layer 29. Its global KV comes from Layer 21, and its selected positions come from Layer 29. It computes its own main query and local KV. Select a box to inspect the operation.

Token dimensions and training conventions

T counts current query/local positions; G counts new global source positions; S counts retained global entries. R = 6T counts routed token-expert assignments. During optimized decoder prefill, the global projection can process the full encoder prompt while the query/local path processes 128 replay positions. Encoder pooling emits only completed pairs, including any carried partial pair. Batch/document boundaries are suppressed here; causal masks preserve them. Deployment can fuse several logical operations into one kernel.

Four residual streams bypass each dense sublayer and are mixed back at its mHC merge. Layer 30 reads its own local KV, L21 global KV, and L29 position indices.

04 / Memory ownership and sparse reading

CSA2: separate producing, selecting, and reading

Each attention layer reads its local window plus at most 512 selected global entries. Main queries are always layer-specific. The three modes decide who makes the global memory and who chooses its positions.

CSA2 computation responsibilities
Mode Examples Global KV + indexer K Indexer query + Top-K Main query + local KV
Full L3, L9, L15, L21 Generate new memory Compute fresh selection Compute independently
Reindex L25, L29, L33, L37 Reuse L21 memory Own query; fresh selection Compute independently
Reuse 30 layers, including L30 Reuse the group's memory Reuse latest Top-K; no indexer query Compute independently

Encoder groups compress pairs

L3–8, L9–14, and L15–20 each have a separate global store at ratio 2:1. A learned channel-wise softmax pools each pair; groups do not overlap.

One global store spans the decoder

L21 projects H20 at ratio 1:1. All 20 decoder layers share this store. Four deeper indexers update which entries their groups read.

Hierarchical indexing bounds the deeper searches

L21 / initial searchFull visible context

Score causally visible positions. Select Top-512 for L21 and score each 8-position block by its maximum.

Shared candidate pool≤16,384

Keep up to 2,048 blocks × 8 positions. The pool is larger than the final attention selection.

L25 / L29 / L33 / L37≤512

Each Reindex layer rescores only the candidate pool with its own indexer query, then selects its own Top-512.

The first search still grows with context length. Later decoder searches are bounded by the fixed candidate pool. Reuse layers perform no search. The candidate restriction is introduced during post-training and applied during inference.

Worked example / reduced sizes, invented scores

Compression, candidates, and selected positions are different steps

First, an encoder example: 12 input positions form six non-overlapping pairs. Learned channel-wise softmax weights pool each pair into one global latent. These are six stored entries, before any sparse selection.

3 · 4↓E2
5 · 6↓E3
7 · 8↓E4

Now switch to the decoder's separate 1:1 store. The current token is at position 25 of a 32-position sequence. We use 4-position blocks, retain 3 candidate blocks, and select Top-3; the released model uses 8, 2,048, and 512 respectively.

Candidate block Selected for global attention Future / causally masked Current position / 25

The Full layer keeps candidate blocks 1, 5, and 6 by their maximum visible score. Reindex can choose different positions within those blocks. It cannot add a position outside the candidate pool. Reuse keeps those position IDs and computes new main attention with its own query, local KV, and sink. All 25 visible global entries remain stored.

Relative to V4 CSA, the compressor removes overlap and learned absolute position embeddings. Indexer K is projected from the main KV latent before RoPE. The core attention still gathers local and selected global latents, with a per-head attention sink.

The 128-token decoder replay is approximate. Every decoder layer generates its own local KV from its own incoming hidden state.

Local dependencies accumulate across depth, so exact reconstruction can require about 20 × 128 = 2,560 recent positions. 06 / Learned phrase memory

Engram: a huge phrase embedding with a gate

An ordinary embedding maps a token ID to a learned vector. Engram maps recent 2-, 3-, and 4-token groups to learned vectors. The current hidden state decides how much of that memory to add to each residual stream.

Recent token IDs2-, 3-, and 4-grams
→
Hash addresses8 heads per order
→
Learned table rows24 × 256 channels
→
Projection + gateCurrent hidden state controls injection
One Engram module / addressing demonstration
24 fetched vectors × 256 channels = 6,144 channels

Concatenate 8 hash-head vectors for each of 3 orders. A learned projection produces four keys and one shared value.

[T, 6144] → Wkv → keys [T, 4, 5120] + value [T, 5120]
H1 + β1 · VH2 + β2 · V H3 + β3 · VH4 + β4 · V

Updated stream = H + 0.60 × V

The actual model computes a gate separately for each stream from normalized hidden/key compatibility. Words here are illustrative tokens; the release hashes compressed tokenizer IDs using multiple heads and distinct prime table sizes. The slider demonstrates gating and does not run the model.

48 rowsaccessed per text token across both modules
12 KiBraw FP8 lookup payload, before scales and communication
196.6Btable elements derived from the released config

Capacity grows faster than arithmetic

Only a few rows are accessed per token. The huge table adds learned pattern capacity with small projections instead of evaluating all table parameters.

Addresses are available early

Lookup addresses depend only on token IDs. Embeddings can be prefetched before a stage runs, overlapping transfers with GPU computation.

Context controls the contribution

The same short phrase can appear in different contexts. Gating allows its retrieved vectors to contribute differently to the current hidden state.

Stored model weights, trained end to end

Engram entries persist across requests as model parameters. Training updates selected rows; inference reads them. KV caches instead hold request-specific activations.

Modules sit at L2 and L15 (release indices 1 and 14), with 8 hash heads per order and about 16M entries per head. The V4.1 variant omits the original Engram short causal convolution and uses momentum plus Sinkhorn balancing for table updates. Table storage and lookup bandwidth remain substantial; the report does not give an isolated Engram accuracy ablation.

Report §2.4.2, §3.1.3, and Engram addressing code.

07 / Open the components

The other pieces of the design

CED and CSA2 target long-context compute and cache storage. These additions address residual traffic, numerical formats, vision, and generation throughput.

Inside the MoE / six routed experts + one shared expert per token

Each text expert uses bounded SwiGLU

Gate and up projections each produce 2,304 channels. The gate has an upper bound of 10; the up branch is bounded at both −10 and +10. Ordinary SiLU transforms the gate, then multiplies it by the up branch before the down projection.

Gate branch / W1g → min(g, 10) → SiLUSiLU(g) = g × sigmoid(g)
Up branch / W3u → clamp(u, −10, 10)Multiply with the transformed gate
SiLU(bounded g) × bounded uFP32 product → routed weight if present → input dtype → W2 down projection to 5,120 channels

Try a negative gate below −10: it stays below −10. Only the gate's upper end is clamped.

Scalar browser math illustrates the function; it does not emulate BF16 rounding or a GPU kernel.

gate = gate.float().clamp(max=10)
up = up.float().clamp(min=-10, max=10)
hidden = F.silu(gate) * up
if route_weight is not None:
    hidden = route_weight * hidden
output = w2(hidden.to(input_dtype))

The reference evaluates the activation in FP32. Routed experts apply their selected routing weight before the cast and W2; the shared expert has no routing weight. The vision encoder uses ordinary SwiGLU; its language-width projector uses GELU.

Reference Expert.forward and Report §3.1.1 specify the activation and limit.

Depth / residual mixing

Single-Pass mHC

Each sublayer predicts input, output, and residual mixing coefficients. The input mix used now comes from the previous sublayer, removing a reduction dependency from the critical path.

X[l+1] = B[l] X[l] + C[l] F(A[l-1] X[l])

Mega-mHC fuses residual update, input mixing, coefficient prediction, pre-norm, and FP8 conversion. The report halves mHC activation traffic relative to its original implementation; this is a residual-module saving.

The final stream merge consumes the carried mixing coefficients too.

Precision / cache layout

FP4 main KV

Quantize the full 512-channel latent after RoPE into E2M1, with one E4M3 scale per 16 channels and no second-level global scale.

512 × 4 bits + 32 × 8-bit scales
= 288 bytes per main KV entry

Attention dequantizes cached values before using them. Main KV QAT is introduced during post-training. Local SWA KV stays FP8 because it is more sensitive to quantization.

Native multimodal input

DeepSeek-ViT

A 32-layer, width-1024 ViT uses 16 heads, 2D RoPE, RMSNorm, and SwiGLU. Linear patch embedding keeps the projection compatible with Muon.

1344×1344 image → 96×96 patches
3×3 unshuffle → 32×32 visual tokens
MLP projector → 5120 channels

At that resolution, 9,216 patch tokens become 1,024 language-model visual tokens. Image and text expert routing have separate load-balancing correction biases.

Generation / speculation

DSpark

Three drafter blocks produce base logits for five draft positions in parallel. A lightweight Markov head models token dependencies; a confidence head estimates acceptance probabilities.

3 draft blocks → 5 positions
Confidence + engine load → verification length

The scheduler adapts verification length to expected system throughput. DSpark is trained after backbone pre-training, then kept aligned during post-training without sending its objective's gradients into the backbone.

Report §2.4 and §2.1.1.

08 / Systems and evidence

Training needs explicit ownership and lifetimes

The report pre-trains on 45T multimodal tokens, using sparse attention from the start at 64K context. Context expands to 1M at 34T tokens. Teacher-forced execution keeps the full 40-layer graph; shared activations introduce distributed responsibilities.

Reuse shares an activation; gradients return to its producer

dKV21 = sum of contributions from decoder attention at L21 through L40

The drawing shows four representative consumers; all 20 decoder layers contribute. Gradients to selected global values sum at the L21 producer, then flow into its projection weights and H20. The sequential hidden-state path also backpropagates normally. Integer position IDs are discrete; indexer training uses a separate objective and gradient policy.

Unselected rows receive no gradient from this lookup. Repeated accesses to a row accumulate. Token-to-address hashes carry no gradient; the fetched vectors, projection, and context gate are learned. Row numbers here are illustrative.

Shared attention state

Carry values and their gradients

Shared KV, indexer keys, and selections can cross pipeline stages. Per-microbatch state tracks their consumers through forward, recomputation, and backward, retaining them until the last consumer finishes.

Engram parallelism

Shard rows, prefetch lookups

Dedicated process groups own table row partitions. Prefetch begins before stage microbatches. Lookup gradients are buffered and returned to their owning ranks after backbone backward; optimizer states are further sharded.

Optimizer allocation

Match updates to the matrices

Backbone linear matrices use Muon, with head-wise treatment for Q/K. Engram tables, token embeddings, and prediction heads use momentum plus Sinkhorn balancing. RMSNorm and other non-matrix parameters use AdamW.

Reference / Capacity accounting

Two kinds of model capacity

The backbone stores most of its weights in routed expert matrices. Engram adds a second form of sparsity: token-addressed table rows. Both activate a small subset of their stored capacity at each position.

Reported headline counts / approximately 748B combined
Backbone / 552B
Engram / 196B

Routed expert bank: 543.58B

40 layers × 384 experts × 3 SwiGLU matrices. Each expert has gate/up/down matrices between model width 5120 and expert width 2304.

40 × 384 × 3 × 5120 × 2304
= 543,581,798,400 matrix parameters

A token selects 6/384 of the routed bank, plus one shared expert in every layer. Main attention, norms, projections, embeddings, and output head add the remaining backbone weights.

Engram tables: 196.61B

The released config specifies two row totals and 256 channels per row. This tally counts table elements, separately from projection and gating parameters.

(384,006,168 + 384,016,682) × 256
= 196,613,849,600 table elements

At one FP8 byte per element, raw tables occupy about 183.11 GiB, before scales. Only 48 rows are selected per text token across the two modules.

The report's 552B and 196B are headline counts rather than a complete checkpoint tensor audit. Its 8B prefill / 16B decode figures describe the optimized execution path. Parameter counts, active arithmetic, stored weight bytes, training optimizer state, and KV memory are different quantities.

The main format has one scale per 16 channels. The indexer uses one scale per 32 channels. Both keys and values of main attention use the stored latent.

The independent-cache comparison uses the same 38 CSA2 layers, widths, compression ratios, and precision, with a separate global store at every layer.

Reported runtime KV: roughly 1/4 of V4 Flash

CSA2 sharing and FP4 main KV jointly reduce the actual long-context serving footprint. At 1M tokens, global KV is 890 MiB in the logical model.

Reported persistent KV: roughly 1/8

Global KV stays in persistent storage. Encoder SWA state uses a short-lived memory pool; decoder SWA is rebuilt from the prompt tail. Bounded replay recovers missing local state.
