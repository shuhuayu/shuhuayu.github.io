03 / Follow the hidden state

One block, with its memory sources attached

Start with Layer 30, a decoder Reuse layer. Its incoming hidden state comes from Layer 29. Its global KV comes from Layer 21, and its selected positions come from Layer 29. It computes its own main query and local KV. Select a box to inspect the operation.

Token dimensions and training conventions

T counts current query/local positions; G counts new global source positions; S counts retained global entries. R = 6T counts routed token-expert assignments. During optimized decoder prefill, the global projection can process the full encoder prompt while the query/local path processes 128 replay positions. Encoder pooling emits only completed pairs, including any carried partial pair. Batch/document boundaries are suppressed here; causal masks preserve them. Equations behind the block / Single-Pass mHC

A reads four streams; B and C update the residual

The equations below show one token: X contains four D-dimensional residual streams, and x and Y are single D-dimensional vectors. All stream mixing is per token. For T tokens, the stored tensor shapes are:

X [T, 4, D]A [T, 4]B [T, 4, 4]C [T, 4]

A: four streams into one input

x = Aprev X
x = ∑i=03 Aprev,i Xi

[4, D] → [D]

The carried A weights the four incoming streams. Attention or MoE then computes Y = F(x), including its input RMSNorm.

B: mix the old residual streams

R = B X
Rj = ∑i=03 Bj,i Xi

[4, D] → [4, D]

Each row of B specifies how the four incoming streams contribute to one updated residual stream j.

C: distribute the new output

U = C Y
Uj = Cj Y

[D] → [4, D]

Each C value scales the same attention or MoE output Y before adding it to its destination stream.

Residual update after either sublayer
Xnext = R + U= B X + C Y

The result still has four streams. In matrix notation, A is a row vector and C is a column vector; C Y distributes the output across streams. B acts on the incoming residual, and C acts on the new sublayer output.

Two coefficient sets and two residual updates per transformer layer

Attention half

Predict (Aattn, Battn, Cattn) from Xin.

xattn = Aprev Xin
Yattn = Attention(xattn)
Xmid =Battn Xin +Cattn Yattn

Aattn is carried to this layer's FFN input.

MoE / FFN half

Predict (Affn, Bffn, Cffn) from Xmid.

xffn = Aattn Xmid
Yffn = MoE(xffn)
Xout =Bffn Xmid +Cffn Yffn

Affn is carried to the next layer's attention input, or the final stream merge after L40.

The Single-Pass shift: the current input uses Aprev, already available from the preceding sublayer. Input mixing can therefore share a traversal of the residual with prediction of the current A/B/C. L1 starts with Aprev = [1/4, 1/4, 1/4, 1/4]. The two sublayers have separate learned coefficient predictors.

04 / Memory ownership and sparse reading

CSA2: separate producing, selecting, and reading

Each attention layer reads its local window plus at most 512 selected global entries. Main queries are always layer-specific. The three modes decide who makes the global memory and who chooses its positions.

CSA2 computation responsibilities
Mode Examples Global KV + indexer K Indexer query + Top-K Main query + local KV
Full L3, L9, L15, L21 Generate new memory Compute fresh selection Compute independently
Reindex L25, L29, L33, L37 Reuse L21 memory Own query; fresh selection Compute independently
Reuse 30 layers, including L30 Reuse the group's memory Reuse latest Top-K; no indexer query Compute independently

Encoder groups compress pairs

L3–8, L9–14, and L15–20 each have a separate global store at ratio 2:1. A learned channel-wise softmax pools each pair; groups do not overlap.

One global store spans the decoder

L21 projects H20 at ratio 1:1. All 20 decoder layers share this store. Four deeper indexers update which entries their groups read.

Hierarchical indexing bounds the deeper searches

L21 / initial searchFull visible context

Score causally visible positions. Select Top-512 for L21 and score each 8-position block by its maximum.

Shared candidate pool≤16,384

Keep up to 2,048 blocks × 8 positions. The pool is larger than the final attention selection.

L25 / L29 / L33 / L37≤512

Each Reindex layer rescores only the candidate pool with its own indexer query, then selects its own Top-512.

The first search still grows with context length. Later decoder searches are bounded by the fixed candidate pool. Reuse layers perform no search. The candidate restriction is introduced during post-training and applied during inference.

Compression, candidates, and selected positions are different steps

Now switch to the decoder's separate 1:1 store. The current token is at position 25 of a 32-position sequence. We use 4-position blocks, retain 3 candidate blocks, and select Top-3; the released model uses 8, 2,048, and 512 respectively.

Candidate block Selected for global attention Future / causally masked Current position / 25

The Full layer keeps candidate blocks 1, 5, and 6 by their maximum visible score. Reindex can choose different positions within those blocks. It cannot add a position outside the candidate pool. Reuse keeps those position IDs and computes new main attention with its own query, local KV, and sink. All 25 visible global entries remain stored.

Relative to V4 CSA, the compressor removes overlap and learned absolute position embeddings. Indexer K is projected from the main KV latent before RoPE. The core attention still gathers local and selected global latents, with a per-head attention sink.

Equations behind the lookup / Engram.forward

From phrase features to a four-stream residual update

At L2 and L15, Engram receives the incoming four residual streams X and the concatenated phrase features E. T counts token positions; r indexes one of the four streams; D = 5120. Batch dimensions are omitted.

X [T, 4, D]E [T, 6144]K [T, 4, D] V [T, D]β [T, 4]X′ [T, 4, D]

1. Project four keys and one value

[Kflat, V] =E WkvT

Wkv [5D, 6144] = [25600, 6144]

E concatenates 24 fetched 256-channel vectors. Split the projection into Kflat [T, 4D] and V [T, D], then reshape the keys to [T, 4, D]. Each stream has its own compatibility key K; all four streams share the same value V.

2. Score memory against each stream

qt,r =RMSNormq(Xt,r)
kt,r =RMSNormk(Kt,r)
st,r =⟨qt,r, kt,r⟩ / √D

Normalize each stream separately over its D hidden features. The learned q_weight and k_weight each have shape [4, D]. The dot product reduces D features to one compatibility score per token and stream: s [T, 4].

3. Turn each score into a gate

zt,r = copysign(√max(|st,r|, δ),st,r)
βt,r = σ(zt,r)

copysign gives the square root the sign of s; δ = 10−6 is the reference clamp. Sigmoid σ(z) = 1 / (1 + exp(−z)) maps this signed score to a gate between 0 and 1. There are four scalar gates per token, β [T, 4].

4. Add the gated value to the residual

X′t,r =Xt,r +mt βt,r Vt

gate [T, 4, 1] × value [T, 1, D]
→ addition [T, 4, D]

mt is 1 for text and 0 for image positions. For each stream, its gate scales all D components of the shared V, and that vector is added to the original X. The four-stream shape is preserved. Image positions receive zero addition.

Expand the RMSNorm used by the gate
RMSNormγ(u) =(γ ⊙ u) /√(mean(u2) + ε)

The mean is over the D features of one token and one stream; γ supplies learned feature scales. The reference computes the score and gate in FP32 and folds the two normalization scales into an elementwise product during the dot product.

Scalar example: if one residual component is 2, the matching value component is 5, and this stream's gate is 0.60, the updated component is 2 + 0.60 × 5 = 5. Each of the other streams uses its own gate with that same value component.

Placement: X′ enters the layer's attention mHC coefficient predictor and four-to-one input mix. Attention and MoE then perform their usual mHC residual updates. Engram's β is its own contextual gate; mHC uses its separate A/B/C coefficients.

Capacity grows faster than arithmetic

Only a few rows are accessed per token. The huge table adds learned pattern capacity with small projections instead of evaluating all table parameters.

Addresses are available early

Lookup addresses depend only on token IDs. Embeddings can be prefetched before a stage runs, overlapping transfers with GPU computation.

Context controls the contribution

The same short phrase can appear in different contexts. Gating allows its retrieved vectors to contribute differently to the current hidden state.

Stored model weights, trained end to end

Engram entries persist across requests as model parameters. Training updates selected rows; inference reads them. KV caches instead hold request-specific activations.

Modules sit at L2 and L15 (release indices 1 and 14), with 8 hash heads per order and about 16M entries per head. The V4.1 variant omits the original Engram short causal convolution and uses momentum plus Sinkhorn balancing for table updates. Table storage and lookup bandwidth remain substantial; the report does not give an isolated Engram accuracy ablation.

Report §2.4.2, §3.1.3, and Engram addressing code. The explicit gate and residual equations follow Engram.forward in the released reference.

07 / Open the components

The other pieces of the design

CED and CSA2 target long-context compute and cache storage. These additions address residual traffic, numerical formats, vision, and generation throughput.

Inside the MoE / six routed experts + one shared expert per token

Each text expert uses bounded SwiGLU

Gate and up projections each produce 2,304 channels. The gate has an upper bound of 10; the up branch is bounded at both −10 and +10. Ordinary SiLU transforms the gate, then multiplies it by the up branch before the down projection.

Gate branch / W1g → min(g, 10) → SiLUSiLU(g) = g × sigmoid(g)
Up branch / W3u → clamp(u, −10, 10)Multiply with the transformed gate
SiLU(bounded g) × bounded uFP32 product → routed weight if present → input dtype → W2 down projection to 5,120 channels

Try a negative gate below −10: it stays below −10. Only the gate's upper end is clamped.

Scalar browser math illustrates the function; it does not emulate BF16 rounding or a GPU kernel.

gate = gate.float().clamp(max=10)
up = up.float().clamp(min=-10, max=10)
hidden = F.silu(gate) * up
if route_weight is not None:
    hidden = route_weight * hidden
output = w2(hidden.to(input_dtype))

The reference evaluates the activation in FP32. Routed experts apply their selected routing weight before the cast and W2; the shared expert has no routing weight. The vision encoder uses ordinary SwiGLU; its language-width projector uses GELU.

Reference Expert.forward and Report §3.1.1 specify the activation and limit.

Depth / residual mixing

Single-Pass mHC

Each sublayer predicts input, output, and residual mixing coefficients. The input mix used now comes from the previous sublayer, removing a reduction dependency from the critical path.

X[l+1] = B[l] X[l] + C[l] F(A[l-1] X[l])

Mega-mHC fuses residual update, input mixing, coefficient prediction, pre-norm, and FP8 conversion. The report halves mHC activation traffic relative to its original implementation; this is a residual-module saving.

The final stream merge consumes the carried mixing coefficients too.

Precision / cache layout

FP4 main KV

Quantize the full 512-channel latent after RoPE into E2M1, with one E4M3 scale per 16 channels and no second-level global scale.

512 × 4 bits + 32 × 8-bit scales
= 288 bytes per main KV entry

Attention dequantizes cached values before using them. Main KV QAT is introduced during post-training. Local SWA KV stays FP8 because it is more sensitive to quantization.

Native multimodal input

DeepSeek-ViT

A 32-layer, width-1024 ViT uses 16 heads, 2D RoPE, RMSNorm, and SwiGLU. Linear patch embedding keeps the projection compatible with Muon.

1344×1344 image → 96×96 patches
3×3 unshuffle → 32×32 visual tokens
MLP projector → 5120 channels

At that resolution, 9,216 patch tokens become 1,024 language-model visual tokens. Image and text expert routing have separate load-balancing correction biases.

Generation / speculation

DSpark

Three drafter blocks produce base logits for five draft positions in parallel. A lightweight Markov head models token dependencies; a confidence head estimates acceptance probabilities.

3 draft blocks → 5 positions
Confidence + engine load → verification length

The scheduler adapts verification length to expected system throughput. DSpark is trained after backbone pre-training, then kept aligned during post-training without sending its objective's gradients into the backbone.

08 / Systems and evidence

Train all 40 layers and return gradients to their sources

The report pre-trains on 45T multimodal tokens, using sparse attention from the start at 64K context. Context expands to 1M at 34T tokens. During ordinary next-token pre-training, every position passes through all 40 layers. Shared KV must reach its consumers, and their gradients must return to its producer. Each active pipeline microbatch needs its own state through forward, recomputation, and backward.

Shared attention state

Carry values and their gradients

Shared KV, indexer keys, and selections can cross pipeline stages. Per-microbatch state tracks their consumers through forward, recomputation, and backward, retaining them until the last consumer finishes.

Engram parallelism

Shard rows, prefetch lookups

Dedicated process groups own table row partitions. Prefetch begins before stage microbatches. Lookup gradients are buffered and returned to their owning ranks after backbone backward; optimizer states are further sharded.

Optimizer allocation

Match updates to the matrices

Backbone linear matrices use Muon, with head-wise treatment for Q/K. Engram tables, token embeddings, and prediction heads use momentum plus Sinkhorn balancing. RMSNorm and other non-matrix parameters use AdamW.

09 / Optimization

Three optimizer families, matched to the parameter

V4.1 uses Muon for backbone matrix weights, head-wise Muon for Q/K, and AdamW for normalization and other non-matrix parameters. The huge Engram, token-embedding, and prediction-head matrices use a Nesterov momentum update followed by Sinkhorn balancing. This saves an optimizer-state buffer while respecting the table's row and feature structure.

Muon / backbone matrices

Transform a momentum matrix

Muon uses an approximate matrix orthogonalization, commonly implemented with Newton–Schulz iterations, to transform the momentum update before applying it to the weights.

Its persistent moment state is one momentum buffer. AdamW maintains both a first-moment and a second-moment buffer.

Head-wise Muon / Q and K

Give each head its own update geometry

The query expansion has shape [64 × 512, 1280]. A logical head view is [64, 512, 1280]: 64 matrices, each [512, 1280].

The report motivates this with differences between heads. A distributed implementation must preserve these logical groups even when physical shards split a head.

Report Algorithm 1 / one table W with m rows and n features

From a gradient to a balanced parameter update

1. Nesterov momentum
Mt = β Mt−1 + (1 − β) Gt
Ĝt = β Mt + (1 − β) Gt

Gt is the gradient, and Mt is the persistent momentum buffer. The reported momentum coefficient is β = 0.95.

2. Alternate row and column normalization
U(0) = Ĝt

Normalize each row by its L2 norm on odd iterations, then each column by its L2 norm on even iterations, adding ε to each denominator. The report uses K = 11 iterations.

Before iterating, zero rows whose norm is at most τ times the mean row norm. The reported constants are τ = 10−3 and ε = 10−20.

3. Scale and apply
Δt = √n · U(K)
Wt+1 = Wt − γηtΔt

√n converts unit row L2 norm into unit row RMS. ηt is the scheduled learning rate; γ = 0.18 adjusts update magnitude. This optimizer applies no weight decay.

What is being balanced?
row RMS(Δ) ≈ 1
column RMS(Δ) ≈ 1

A row identifies a token or hashed phrase. A column identifies a hidden feature. Balancing changes update magnitudes while retaining their signs.

Masked rows remain zero. Finite iterations only approximately balance both axes.

Two uses of Sinkhorn: here it balances a signed optimizer update. In mHC, 20 iterations constrain a positive 4×4 residual-mixing matrix. They act on different tensors.

The reported training schedule

Warm up for 2,000 optimizer steps, hold learning rate at 2.6×10−4 until 28T tokens, cosine-decay to 2.6×10−5 between 28T and 40T, then hold it until 45T. Context extends from 64K to 1M at 34T tokens.

The vision encoder is initially frozen while its final normalization and the vision-language projector train. At the learning-rate decay stage, the encoder is unfrozen with a smaller learning rate.

10 / Infrastructure challenges

Make sparse memory efficient across devices and requests

The architecture reduces repeated KV construction and prompt computation. A practical implementation must also move Engram rows efficiently, preserve shared-state gradients, execute sparse attention on long contexts, and manage the separate global and local cache paths. The items below connect the report's infrastructure designs to the work required in a training or serving system.

1 / Engram capacity and communication

Shard the tables and fetch rows ahead of compute

196B table parameters, their gradients, and momentum state require a distributed layout. Engram row owners must serve lookups and receive accumulated gradients, including repeated addresses.

The report row-shards tables, further shards optimizer state, fetches FP8 rows and scales ahead of pipeline microbatches, and returns buffered gradients after backbone backward. It keeps tables GPU-resident during RL rollouts.

The engineering task: overlap these transfers with useful work while bounding fetched-row buffers and preserving the update for each row.

2 / Distributed optimizer geometry

Keep logical heads and global table statistics intact

Head-wise Muon operates on logical heads. TP or FSDP may physically split those weights. Sinkhorn needs row and column statistics even when embedding rows are spread across ranks.

The report's Engram optimizer maintains scaling vectors between iterations and fuses row normalization with partial column-statistic accumulation, reducing full-matrix writes.

The engineering task: apply the same logical update after sharding, with correct reductions and minimal memory traffic.

3 / Sparse attention and packed formats

Turn selected positions into efficient gathers

Attention reads local KV plus selected global entries. Reuse layers can share KV and selection, while the first hierarchical indexer still searches the visible global history at up to 1M context.

Long-context execution needs consistent causal and document masks, global position IDs, CP partitions, gather/scatter gradients, and the FP4 values and scale layout. Later indexers search the bounded candidate pool.

The engineering task: reuse existing attention math while matching compressed-source relationships, packed reads, and cross-rank selection semantics.

4 / Shared state in pipeline parallelism

Pass KV as a differentiable stage payload

For G21, an intermediate stage receives (H, G21), uses G21 in attention, and forwards (H′, G21). Backward accumulates local and downstream contributions through the ordinary stage graph.

Each microbatch needs separate state through recomputation and backward. Indexer keys, selection IDs, candidate pools, and the carried mHC input coefficients also have producer/consumer contracts. Shadow indexers add parameter synchronization and one logical optimizer/checkpoint owner.

The engineering task: extend stage inputs and outputs and their gradient routes, then validate the existing pipeline schedule with those tensors.

5 / Multimodal input and rollout traffic

Balance image work and avoid repeated preprocessing

Image-dense, million-token sequences stress host I/O and memory. Contrastive vision training also gathers features across data-parallel ranks.

The report overlaps feature communication with compute, runs vision forward/backward around the LLM phase, balances images across CP ranks so each loads once, and caches preprocessing for repeated rollouts.

The engineering task: preserve text/image positions and gradients while balancing vision work and coordinating data movement.

6 / CED serving and prefix reuse

Manage global and local state on different schedules

Global KV supports long-term prefix reuse. Encoder SWA is short-lived; missing state triggers a 128-token replay. Decoder prefill passes only the final 128 encoder outputs through the upper layers to initialize local caches.

Replay is approximate. A serving system must implement both replay paths, preserve cached global KV, append new suffix state, and evaluate quality under different prefix hits. Vision encoding, prefill, and decode can scale independently.

The engineering task: measure cache-hit rate, replay cost, transfer volume, and response quality together.

Two kinds of model capacity

The backbone stores most of its weights in routed expert matrices. Engram adds a second form of sparsity: token-addressed table rows. Both activate a small subset of their stored capacity at each position.
