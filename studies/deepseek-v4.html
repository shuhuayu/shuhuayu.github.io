01 / The big picture

The model at a glance

Compression and sparsity are different

CSA stores one entry per four tokens, then chooses only a subset to read. All compressed entries remain in the cache, even those not selected by this query.

HCA is not fixed-state attention

Its memory still grows with context, at one entry per 128 tokens. It reads all causally available compressed entries instead of running an indexer.

Four streams do not make GEMMs four times wider

mHC contracts the residual state to one D-wide input before each attention or MoE call, then broadcasts the result back with learned mixing.

Most parameters are inactive for any one token

One token touches six routed experts and one shared expert per layer. It does not execute all 384 expert networks in Pro.

03 / Two resolutions of history

Compress first. Select only when needed.

Both paths use shared-key-value multi-query attention: one 512-dimensional memory vector serves as both K and V for all query heads. The last 64 dimensions carry RoPE; attention output receives inverse RoPE before the grouped projection.

CSA: four-token compression, sparse reading

Two KV projections and two gate projections create previous/current candidates. A per-channel softmax pools eight candidates from two adjacent four-token groups into one compressed entry. Groups overlap, so the storage reduction is 4:1, not 8:1.

HCA: 128-token compression, global reading

One KV projection and one gate projection pool each non-overlapping group of 128 tokens into one entry. No lightning indexer is needed: each query reads every completed, causally available compressed block.

The longer pooling interval makes its global memory much smaller. The tradeoff is coarser historical detail; CSA supplies a finer-grained view in the alternating layers.

The local window preserves fine detail and causality. Incomplete future blocks are not available to a query. The 128-token uncompressed window covers recent tokens that compression would otherwise hide. Local and compressed candidates feed the same attention softmax, with a learned per-head attention sink.

04 / Depth and width

Four residual streams. Seven active experts.

mHC: constrain the residual highway

The residual state is T × 4 × D. Before each sublayer, a normalized flattened 4D vector produces 24 mixing values: 4 input coefficients, 4 output coefficients, and a 4 × 4 residual matrix.

stream 2
stream 3
stream 4
Xnext = B X + C F(A X)

Sigmoid bounds A and 2 × sigmoid bounds C. Twenty Sinkhorn iterations make B approximately doubly stochastic: positive entries, with each row and column summing to one. The ideal constrained residual mapping is non-expansive and remains stable under composition.

The expensive sublayer F still receives T × D. The four-way expansion affects residual storage and the small mixing operation, not the attention and expert input widths.

Report §2.2. This is standard V4 mHC, not V4.1 Single-Pass mHC.

DeepSeekMoE: capacity behind sparse routing

Every block owns a bank of fine-grained routed experts and one always-active shared expert. Scores use sqrt(softplus), with a balancing bias affecting selection but not the gathered expert weights.

expert(x) = W2 [SiLU(W1x) ⊙ W3x]

The first three layers select experts using a token-ID hash table; later layers use score-based top-6 selection. Both execute real MoE networks. The reference clips SwiGLU activations to limit outliers.

A packed input of T tokens generates 6T routed assignments. Expert parallelism redistributes those assignments to expert owners, combines their weighted outputs, and adds the shared expert result.

06 / What grows with context

A smaller cache, not a constant-size cache

Only completed blocks occupy compressed history. CSA keeps N/4 main entries and N/4 index entries per layer; HCA keeps N/128 main entries. The local ring buffer saturates at 128 entries per layer.

Mixed payload = 448 FP8 + 64 BF16 main dimensions (576 bytes), and 128 FP4 index dimensions (64 bytes). One main entry serves as both K and V, shared across all query heads.

07 / The optimizer is part of the recipe

Eight fast steps. Two stabilizing steps.

The V4 report explicitly uses hybrid Newton–Schulz orthogonalization inside every Muon update: eight iterations of the fast quintic, followed by two of a convergent polynomial. This is V4's published choice, not a universal Muon default.

Per-iteration polynomial coefficients

X ← aX + b(XXT)X + c(XXT)2X
  • Iterations 1–8(3.4445, -4.7750, 2.0315)
  • Iterations 9–10(2.0, -1.5, 0.5)
  • Muon momentum0.95 + Nesterov
  • Weight decay0.1

A singular value s follows p(s) = as + bs3 + cs5. The fast polynomial expands small values quickly but does not fix s = 1. The final polynomial has p(1) = 1 and p′(1) = 0.

Report §2.4, Hybrid Newton-Schulz Iterations. The schedule repeats inside each optimizer update; it is not a schedule over training steps.

Muon needs the whole logical matrix. Sharding storage is compatible with Muon only if the distributed optimizer reconstructs the required matrix view for orthogonalization. The report optimizes experts independently; a physical shard or a stack of unrelated experts is not automatically the right matrix.
08 / Making the model runnable

Balance matrices, tokens, and saved tensors

The report's system combines expert dispatch with a hybrid ZeRO strategy for Muon. Dense matrices are assigned to bounded-size groups; MoE matrices are split by expert identity so that each expert can be orthogonalized independently.

1 / RouteToken scores or hash IDs choose six experts
2 / DispatchMove token assignments to expert owners
3 / ComputeExpert GEMMs and local shared expert
4 / CombineReduce weighted expert outputs
5 / UpdateWhole-matrix Muon, then restore shards

Dense and expert parameters have different ownership

Knapsack-style assignment balances dense matrix sizes. Experts are assigned independently, with data-parallel owners redundant only where the report's hybrid ZeRO policy calls for it.

Batch equal-shaped NS work

The report merges consecutive same-shaped matrices into batched Newton–Schulz computations. This improves utilization without making those matrices a single larger orthogonalization problem.

Low-precision communication still needs accurate reduction

MoE gradients are stochastically rounded to BF16 for communication. The report uses all-to-all exchange and a local FP32 sum to avoid low-precision collective accumulation errors.

Checkpoint tensor dependencies, not just modules

Tensor-level checkpointing, fused MoE kernels, and recomputed mHC intermediates reduce saved activation memory. The diagram's checkpoint option illustrates dependencies, not a measured peak-memory budget.
